# 开发

## 环境

- macOS 14+，只需要 Xcode Command Line Tools（`xcode-select --install`），不需要 Xcode。
- Swift Package：`swift build`（调试版）、`swift build -c release`（测速、回放用这个，调试版慢 5–10 倍）、`./scripts/build-app.sh`（打包成 `dist/卫戍协议小助手.app`）。
- 开发时也可以 `swift run`（要给终端授予屏幕录制权限）。

## 离线调试命令

```bash
.build/debug/GarrisonHelper --selftest 截图.png [追踪名称…]
.build/debug/GarrisonHelper --plan "禁用盟约1,禁用盟约2" "持有干员1,持有干员2" [策略id] [终端等级] [敌方领袖] [特训敌人,…]
.build/debug/GarrisonHelper --field 截图.png     # 场上认人
.build/debug/GarrisonHelper --actions 截图.png 标注.png main=本家 [owned=a,b] [money=N]   # 推荐操作，输出标注图
.build/debug/GarrisonHelper --board 截图.png 标注.png      # 战场识别，画出格子和敌人路线（ROUND=8 [MAP=m04 MODE=终极模拟 BOSS=enemy_id] 画这回合的真实路线；调试记录里的帧直接用）
.build/debug/GarrisonHelper --replay a.png b.png …          # 按顺序跑完整实时流程（REPLAY_RETINA=1 模拟 2× 的 Retina 截图）
.build/debug/GarrisonHelper --hud a.png b.png …             # 回合 / 资金 / 终端等级（BADGE_DEBUG=目录 保存资金数字裁块）
.build/debug/GarrisonHelper --place map=m04 team=折桠,烈夏,… [at=折桠@0,3;烈夏@1,2] [round=8 mode=终极模拟 boss=enemy_id]   # 站位建议（格子、朝向、理由）；给 round 时按这回合的真实路线
.build/debug/GarrisonHelper --miniboard map=m04 round=8 team=… at=… out=小地图.png   # 把侧栏小地图画成图片
.build/debug/GarrisonHelper --make-level-templates out.json 4:a.png 5:b.png …   # 从截图重建终端等级模板
```

调试模式存下的 png（已经是缩小后的识别图）也可以直接喂给这些命令。

输入是一整张游戏窗口截图，命令会输出 OCR 文本、商店命中和准备页识别结果。设置页的「保存当前截图和 OCR 结果」可以生成这类截图（存在 `卫戍助手调试/手动截图/`）。

## 回归检查

改了识别、阵容、建议相关的代码后跑：

```bash
scripts/regress.sh
```

它用 release 版把 `../调试文件/回归检查/cases.txt` 里的每个用例（调试记录里的帧）重跑一遍，去掉耗时后和上次认可的输出逐行比较，有变化就列出 diff 并返回失败（约 1 分钟）。确认变化是对的（修好了 bug，或者结果更好）之后：

```bash
scripts/regress.sh record
```

用例格式：`名字 | 环境变量 | 命令`，例如 `eliminated | ELIM_SECONDS=0 | --replay a.png b.png …`。用例和期望输出都在仓库外的 `../调试文件/回归检查/`（含个人画面；用例里的帧在 `../调试文件/对局记录/`）。小助手新存的调试记录先在 `dist/卫戍助手调试/`，要用作用例时搬到 `../调试文件/对局记录/`；修一个识别问题时，把那几帧加成一个用例。

## 调试模式

「设置 → 识别 → 调试模式」打开后，实时识别会把画面和识别结果（HUD、顶栏、商店卡与价格、战场、场上干员、阵容、推荐操作、OCR 原文）存到**小助手所在文件夹**下的 `卫戍助手调试/开局日期_时间/`（例如 `dist/卫戍助手调试/2026-11-22_2010/`），不会写到别处：

- 每局一个文件夹（点「开始新的一局」、自动识别到新的一局或停了 15 分钟以上就开新文件夹）。
- 休整期最多 2 秒一帧，识别结果没变时 30 秒一帧（画面大变，比如出现没见过的弹窗，照存）；作战中每 10 秒一帧；每局最多 1000 帧（PNG 无损：试过 JPEG，8 帧里有 3 帧认人结果变了，回放就对不上实战）；磁盘剩余不到 15 GB 时不存。
- 设置里能看到已存多少局、占多大，可以打开文件夹或把记录移到废纸篓。

遇到识别不对，把那一局的文件夹（或那一帧的 png 和 json）发来即可复现。小人模型编译后的缓存仍在「~/Library/Application Support/GarrisonHelper」，不是调试记录。

## 速度

用 release 版（`scripts/build-app.sh`）在 M4 上实测：

- **一次完整读取约 0.1–0.25 秒**：全屏文字识别（神经网络引擎，独立的 OCRWorker 进程）约 0.1 秒，同时在本进程里读商店名称栏、在神经网络引擎上认场上的人、在 CPU 上对棋盘，三路并行，不再一个接一个。
- **休整期每一轮都完整读取**（以前三轮才读一次 HUD、资金和场上），买完人、刷新后下一轮（约 1 秒）就更新；作战中三轮读一次。
- **画面没变就不读**：两帧差别很小（闲置时约 0.2–0.5，有变化时 10 以上，阈值 0.8）就直接沿用上一次的结果，只刷新建议和高亮；每几秒仍补读一次。
- **认人约 5 毫秒（11 个单位）**：找阶级角标 4 ms，把每个小人直接画进模型要的 160×192 输入缓冲区 2–3 ms，神经网络引擎推理 2–3 ms。以前把图片交给 Core ML 自己转格式要 90–125 ms，改掉后认出的结果逐行一样。整帧耗时由全屏文字识别（约 0.13 秒）决定，认人本来就和它并行，所以省下的是 CPU（更省电、不发热）。推理在 CPU / GPU / 神经网络引擎上都只要几毫秒，换显卡（CUDA 只有 NVIDIA 显卡有，Mac 上没有）不会更快。
- 小数字（刷新价、卡价）模板读不出来时才用 Vision，结果按数字的笔画缓存，同样的数字不再重复识别。
- 阵容变化后重新规划路线约 1–1.5 秒，一次只跑一个，期间来的变化合并成下一次。
- 第一次开「实时」时系统要编译文字识别模型（几秒到几十秒，磁盘空间够时之后会缓存），开实时时就在后台预热。

`TICK_TIMING=1` 跑 `--replay` 打印每一步耗时，`SPRITE_TIMING=1 [SPRITE_UNITS=ane|gpu|cpu] --field 截图.png` 打印认人的各步耗时，`REPLAY_LIVE=1` 让回放按实时的节奏（画面没变就跳过）；调试版（`swift build`）慢 5–10 倍，测速要用 release。调试记录的 json 里也有每一轮的耗时（`timing`）。

## 版本号与发布

- 版本号在 `VERSION`，三段 `主.次.修订`（macOS 的版本号最多三段，不能用 0.0.0.1）：平常的发版（修 bug、加一两个功能，如替补建议、音乐播放器）都只加修订号（0.4.0 → 0.4.1）；只有大改版（大量功能或界面重做）才加次版本号并把修订号归零（→ 0.5.0），不兼容的变化加主版本号（→ 1.0.0）。拿不准时加修订号。`build-app.sh` 把它写进 Info.plist，构建号用提交数，另外写入提交哈希（有未提交改动时带 `-dirty`）。设置 → 关于、调试记录的 json（`version`）里都能看到，报问题时就知道是哪一版。
- 每次发版：
  1. 在本机跑 `scripts/regress.sh`（要用 `../调试文件/` 里的录像，GitHub 上跑不了）和 `scripts/privacy-check.sh`。
  2. 改 `VERSION`，在 `CHANGELOG.md` 写 `## x.y.z — 日期` 这一节（这一节就是 Release 说明，只写用户关心的变化，不写调试过程和对局录像），详细的问题、改法、验证写进 `docs/开发记录.md`，提交。
  3. 打标签并推送：`git tag v0.3.0`、`git push origin main v0.3.0`。
  4. GitHub Actions（`.github/workflows/release.yml`）在 macOS 上从这个标签重新编译，自动做这些事：
     - 核对标签和 `VERSION` 一致；
     - 跑隐私检查和不需要录像的自检；
     - 打包成 DMG（打开后是小助手和「Applications」快捷方式，拖过去就装好了），算 SHA-256；
     - 加构建来源证明；
     - 建一个**草稿** Release，说明取自 CHANGELOG 里这一版的那一节，末尾附安装说明、校验方法，以及上一版以来的每个提交（哈希链接到该提交）和完整对比链接。
  5. 下载草稿里的 DMG 试一下，没问题再在 GitHub 上点「Publish release」。
- 发布的 app 只从 GitHub 上编译，不上传本机打的包（本机 `Resources/` 以外的东西、调试记录都不会混进去）。

## 签名（屏幕录制权限不用每次重新勾）

macOS 按应用的签名记屏幕录制权限。临时签名（ad-hoc）每次构建都变，macOS 会当成新应用，要重新勾选。所以发布版统一用一张固定的自签名证书「GarrisonHelperMac Release」（SHA-1 `6619c5e8…7e8e00`，2046 年到期）签名：签名要求是「bundle id + 这张证书」，换版本不变，权限就一直保留。它不是 Apple 开发者签名，第一次打开仍要在「隐私与安全性」里点「仍要打开」。

- 证书在维护者本机 `~/Library/Application Support/卫戍协议小助手-签名/`（`signing.p12`、`p12-password.txt`、`cert.pem`，权限 700 / 600），不进仓库，也不导入钥匙串。**要备份**：丢了只能换新证书，所有人更新后要再勾一次权限。
- GitHub 上存成两个 Actions secrets：`SIGN_P12_BASE64`（p12 的 base64）和 `SIGN_P12_PASSWORD`。发布流程只在构建那一步用它，并检查签名的证书指纹；没有 secret 就直接失败，不会发出临时签名的版本。
- `build-app.sh` 的顺序：`SIGN_P12`（发布用；本机有上面那个文件夹时自动用，所以本机打包也不用再勾权限）→ `SIGN_IDENTITY` 或钥匙串里名为 `卫戍协议小助手 本地签名` 的证书 → 临时签名。p12 导入一个用完就删的临时钥匙串文件，不改登录钥匙串和钥匙串搜索列表。
- 换证书：重新生成 p12，更新两个 secret 和 release.yml 里的 `RELEASE_CERT_SHA1`。

## git 约定

- `main` 始终能构建；较大的改动开分支（`feature/敌人路线`、`fix/悬赏标题`），做完合回 `main`。
- 提交前：`swift build` 通过；动了识别就跑 `scripts/regress.sh`。
- 提交信息第一行写改了什么（中文即可），下面写为什么、怎么验证的。
- 不入库：`../卫戍协议小助手-参考项目/`（上游源码，在仓库外）、`../调试文件/`（仓库外）和 `dist/`（个人截图、调试记录）、`.build/`。API Key 存在 `~/Library/Application Support/卫戍协议小助手/api-keys.json`（权限 600），不在仓库里，也不用钥匙串（临时签名每次重建都会让钥匙串重新要密码）。

- 推送前跑 `scripts/privacy-check.sh`：扫邮箱 / 本机路径 / 密钥，拿本机调试记录里出现过的玩家昵称去搜要发布的文件和全部 git 历史，扫打包好的 app，列出提交作者（应该只有 GitHub 隐藏邮箱）。有问题时退出码是 1。
- 应用图标改动时改 `scripts/make-app-icon.swift`，再运行 `swift scripts/make-app-icon.swift Resources/AppIcon.png`。
- 新加的游戏素材或数据要写进 `ASSETS.md`；移植上游代码的文件开头写明改编自哪个项目（Apache-2.0），对应文件记到 `REFERENCES.md`。

## 更新游戏数据

数据为规程 V3_1 赛季。新赛季时把 StrongholdAssistant 的 `data/*.json` 复制到 `Resources/data/`，敌人路线用 `python3 scripts/build-enemy-routes.py`、替身卡对照用 `python3 scripts/build-prototypes.py` 重新生成（两个脚本都从 `../卫戍协议小助手-参考项目/StrongholdAssistant/data/` 读），排风口气流用 `python3 -I scripts/build-terrain-devices.py <关卡文件目录>`（ArknightsGameData 的 `level_act3autochess_mNN.json`）重新生成，然后重新构建并跑回归检查。
